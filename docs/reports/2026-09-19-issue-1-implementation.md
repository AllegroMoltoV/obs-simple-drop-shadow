# issue #1: 分離型ボックスブラーの実装と検証

確認日: 2026-09-19

## 対応内容

[GitHub issue #1](https://github.com/AllegroMoltoV/obs-simple-drop-shadow/issues/1) の提案に沿い、影のボックスブラーを横方向と縦方向の2パスへ分けた。[エフェクト](../../data/effects/drop-shadow.effect) の横方向パスは元画像のアルファ値を平均し、縦方向パスはその中間結果を平均して元画像と影を合成する。[フィルタ](../../src/drop-shadow-filter.cpp) はOBSの公開描画APIで元画像と中間結果を取得し、毎フレーム描画先をリセットする。旧版の縦横二重ループは削除した。

各パスは半径を `r` とすると1画素当たり `2r + 1` 回サンプルする。2パスの合計は `4r + 2` 回で、旧版のブラー部分は `(2r + 1)²` 回だった。設定上限の半径20では、ブラーのサンプル数は1画素当たり1681回から82回になる。描画パスが1回から複数回へ増えるため、実際のフレーム時間の改善幅は測定していない。

## 画像端の扱い

初期の2パス実装は、画像端の画素と横オフセットを組み合わせると、旧版と異なる位置でClampしていた。5×5画像の左端中央1画素、半径1、横オフセット2のGPU統合テストでは、旧版相当の影アルファ85に対し57になった。横オフセットを横パス、縦オフセットを縦パスで適用するよう変更し、同じテストで85を確認した。正の縦オフセットと負の横オフセットの端ケースも通った。

中間テクスチャは8ビットRGBAである。横パスの値が中間保存時に丸められるため、全画素で旧版と完全に同じ値になることは確認していない。

## 検証結果

Visual Studio 2022で `cmake --build build_x64 --config RelWithDebInfo` が成功した。OBS 31.1.1のDirect3D 11で画素を読み取るCTestは11件すべて成功した。テストは半径0・1・20、画像端と正負の横オフセット、正の縦オフセット、影色と不透明度、設定変更後の次フレームを含む。`clang-format --dry-run --Werror`、`gersemi --check --no-cache CMakeLists.txt`、`git diff --check` も通った。

実フィルタの統合テストは、変更前の描画経路を使うと期待した3×3の影にならず、横一列だけが描画されることを確認してから実装した。画像端のテストも、修正前に期待値85に対し57で失敗することを確認した。実行記録はローカルの `.logs/pipeline-red-test3-20260919.log`、`.logs/edge-red-test-20260919.log`、`.logs/format-test-20260919.log` にある。

`buildspec.json`を0.1.1に更新した配布候補をVisual Studio 2022のRelWithDebInfoで再ビルドし、同じ11件のテストに通した。DLLのFileVersionとProductVersionは0.1.1である。配布候補ZIPのSHA-256は`B744E120A498AED68E1F6F42B8CBFAEBC29F48EEE9146B03DD3005AED5547E25`で、展開した5ファイルはOBSへの設置物と一致した。

利用者は、この版を導入したOBSの実機画面でフィルタ表示、ぼかし半径0・4・20、X/Y位置、色、不透明度を確認し、問題なしと報告した。macOSとLinuxでのビルドと動作、実環境のフレーム時間は未検証である。GitHub releaseは未公開である。
